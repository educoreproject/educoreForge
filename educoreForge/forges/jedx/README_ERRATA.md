# JEDx Open API Specification 1.0.0: observations about the upstream source

Evidence first. Each item was measured on 2026-10-23 over snapshot 02 (`HROpen/APISpecifications`, branch `development`, commit `707ec7d3741df46f6973411e5dd75c756cf3d7d7`), with `python3 -I` scripts kept in `system/dataStores/nextStandards_102326/laneB/scripts/`. These notes are for the publisher (the HR Open Standards Consortium and the JEDx Working Group). They go through BRONZE_CROWN and TQ; the forge never writes to the publisher.

The column "how the forge carries it" records the forge's declared rule. Where that rule waits on the OpenAPI kit's K1 step, the cell says so.

| # | observation | where | how the forge carries it |
|---|---|---|---|
| E1 | The four bundles are **fully dereferenced**: `$ref` occurs 0 times. Every reference is an inline copy of the target schema, and the copy keeps the target's `title`. The copying is what inflates `workers-openapi-bundle_v1.json` to 273,864,811 bytes. That file is over GitHub's per-file limit, which is why the repository carries it only as a zip. | all four `*-openapi-bundle_v1.json` | REFERENCES are recovered by `title` (kit K1, R1). The bundle bytes are git-ignored (README_PROVENANCE.md). |
| E2 | **295 inline copies differ from the component they name.** 184 carry a narrower `enum`; the rest differ in `allOf`, `properties`, `definitions` or `version`. For example, a 4.5 `OrganizationReferenceType` is inlined inside 4.3 types. A further 7 inline titles have no component at all: `MessageBaseType`, `WorkerCompensationType`, `WorkerPaidHoursType`, `TrainingRelationshipCodeList`, `WeekdayCodeList`, `WorkAssignmentCodeList`, `WorkRelationshipCodeList`. 196 inline object schemas have no title. | the bundles' property sites | each such site gets its own node, so the round trip re-emits it exactly (kit K1, R2) |
| E3 | **Mixed HR Open schema versions in one bundle.** The inlined types' `version` keyword reads 4.3.0 at 37,729 sites, 4.5.0 at 1,015, "4.3.x" at 85 and "4.5" at 5. The last two are not version numbers in the form the others use. | `version` on inline schemas | carried verbatim on each node; never normalised |
| E4 | **`title` and component name disagree on 39 components.** These include the 12 API envelope wrappers named `*-schema_v1`, and three lower-case names whose titles are capitalised: `messageBaseType`, `confirmMessageType` and `workerNounType`. `confirmMessageType` and `ConfirmMessageType` are both components. | `components.schemas` keys vs `title` | the component NAME is the identity; `title` is carried as data |
| E5 | **The plain specifications carry no schemas.** `*-openapi_v1.json` `$ref`s `../../../../common/json/...`, the HR Open schema library, which is not in the public repository. Only the bundles are self-contained. | `*/v1/*-openapi_v1.json` | not read by the forge |
| E6 | **The publisher's "Final" lags its own repository.** `hropenstandards.org/jedx-open-api-specifications` says "Finalized 10/15/2024". The same four files were changed later: on 2024-11-18, 2024-11-19 and 2024-11-22, 2025-01-27, 2025-05-27 ("Updated schema per requirements gap analysis") and 2025-06-12. `info.version` stayed `1.0.0` throughout, so the version number does not distinguish the releases. | the website vs the git log | snapshot 02 pins the commit, not the version string |
| E7 | **The repository states no licence.** GitHub reports `license: null` and there is no LICENSE file. The HR Open License Agreement is published separately, and its preamble says that obtaining or using the Work is acceptance. | the repository | the licence PDF is carried as a peer of the snapshot; downloads are withheld under the agreement's §2.f until TQ rules |
| E8 | **A newer partial model sits beside the specification.** `transport-objects/` (2026-01-30 to 2026-02-12) holds five JSON Schema draft-07 entities and five code sets. The publisher describes it as "subsets of the larger set … for … a specific infrastructure". Its field names are not HR Open's: `RefId`, `senderId`, `receiverId`, `podURL`. | `transport-objects/schemas/` | carried as a committed peer, not forged (BRONZE_CROWN ruling); see `CHANGES-jedx-01to02-102326.md` |
| E9 | **The work order's branch is gone.** The JEDx proposal names branch `jedx-project-1`. It was merged into `development` by PR #1 on 2025-10-02 and no longer exists. | the repository's refs | the acquisition recipe names `development` and a commit |

**Not a forge observation; recorded for the change record.** The July CSV the graph used to hold (snapshot 01) is an export of an earlier version of E8's transport objects: 112 of its 131 paths match. It is not an export of the specification.
